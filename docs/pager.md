# Pager 与页面生命周期

实现：[`src/storage/pager.zig`](../../src/storage/pager.zig)。

## 页面与文件映射

- `page_size` 固定为 4096 字节，页号从 0 开始；文件偏移为 `page_id × 4096`。
- `Page` 在内存中包含 `id`、`dirty` 和 4096 字节 `data`。文件只保存 `data`，控制字段不落盘。
- `Pager.open` 打开或创建文件，不截断已有内容。
- `getPage(id)` 先查 `AutoHashMap` 缓存；首次读取时按位置读取，文件尾部不足一页的部分补零。之后返回同一个缓存页指针。
- `allocatePage()` 以文件长度向上取整，并考虑当前缓存中最大的页号，分配零填充的脏页。页号超过 `u32` 范围时返回 `PageIdExhausted`。已分配但还没写入的页也会由缓存高水位避免重复分配。
- `flushPage(id)` 只处理已缓存且标记为脏的页；未缓存返回 `PageNotCached`。整页写成功后清除 dirty 标记。
- `close()` 尝试刷新缓存中所有脏页，随后释放缓存、关闭文件。它会继续尝试其他页的刷新，并在清理后返回首个刷新错误。

页面没有 pin/unpin，也没有淘汰策略；所有读过的页面都留在缓存直到关闭。该实现提供缓存和写回，不提供事务保护或崩溃一致性。
